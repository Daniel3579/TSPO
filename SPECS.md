# ТЕХНИЧЕСКОЕ ЗАДАНИЕ
## Разработка веб приложения для оценки финансовой надежности компании

### 1. Основание для разработки
Разработка обусловлена необходимостью методической и архитектурно‑функциональной основы для разработки масштабируемого сервиса, который обеспечивает:
- сбор данных
- расчёт коэффициентов
- рейтинговую оценку
- анализ рисков

### 2. Назначение разработки
Создание веб приложения для оценки финансовой надежности компании

### 3. Цели разработки
Систематизация результатов проектирования прототипа веб‑сервиса для оценки финансовой надёжности компании

### 4. Требования к функциональным характеристикам
- Загрузка данных: подгрузка данных с AlphaVantage
- Расчёты: финансовые коэффициенты (ликвидность, долговая нагрузка, динамика)
- Аналитика: графики, межфирменное/отраслевое сравнение, рейтинги, индекс рисков
- Отчётность: документы для инвестиционного/кредитного/внутреннего использования

### 5. Требования к надежности
- Гарантированное сохранение финансовой оценки
- Восстановление после сбоев
- Резервное копирование данных

### 6. Условия эксплуатации
- Веб-доступ через стандартные браузеры
- Поддержка мобильных устройств

### 7. Требования к составу и параметрам технических средств
- Сервер с ОС Linux
- СУБД PostgreSQL 17+
- Веб-сервер Apache/Nginx
- GO 1.22+

### 8. Требования к информационной и программной совместимости
- Соответствие стандартам HTML5, CSS3
- Поддержка современных браузеров

### 9. Стадии и этапы разработки
1. Проектирование архитектуры
2. Разработка ядра системы
3. Создание веб интерфейса
4. Реализация системы расчета финансовой оценки
5. Тестирование и отладка

### 10. Порядок контроля и приемки
- Функциональное тестирование всех модулей
- Проверка безопасности системы
- Приемочные испытания с участием конечных пользователей
- Анализ соответствия требованиям ТЗ

# ОПИСАНИЕ ПРОГРАММЫ
## "Веб приложения для оценки финансовой надежности компании"

## 1. Общие сведения

### 1.1. Обозначение и наименование программы
- **Обозначение:** Financial-assessment
- **Наименование:** "Веб приложения для оценки финансовой надежности компании"  
- **Краткое наименование:** ФинНадёжность

### 1.2. Программное обеспечение, необходимое для функционирования
- Веб-сервер Nginx
- СУБД PostgreSQL 17+
- Среда выполнения Go 1.22+
- Среда выполнения Node.js
- Веб-браузер с поддержкой HTML5, CSS3, JavaScript ES6+
- Docker

### 1.3. Языки программирования
- Go 1.22+ (серверная часть, обработка бизнес-логики)
- TypeScript + Vue 3 (клиентская часть, интерактивные дашборды)
- HTML5 (разметка страниц)
- CSS3 (оформление и адаптивный дизайн)
- SQL (работа с базой данных)

## 2. Функциональное назначение

### 2.1. Класс решаемых задач
Программа предназначена для решения задач финансового анализа и поддержки принятия управленческих, инвестиционных и кредитных решений, а именно:
- Автоматический сбор и консолидация финансовых данных
- Расчёт ключевых финансовых коэффициентов (ликвидность, долговая нагрузка, рентабельность, динамика показателей)
- Рейтинговая оценка надёжности компании
- Анализ рисков на основе исторических и сравнительных данных

### 2.2. Назначение программы
Создание централизованного веб-сервиса для оперативной и сопоставимой оценки финансовой надёжности компаний, позволяющего заменить разрозненные инструменты (Excel, локальные БД, внешние сервисы) и снизить риски ошибок при анализе

### 2.3. Функциональные ограничения
- Программа не принимает инвестиционных или кредитных решений автоматически – результаты носят рекомендательный характер
- Корректность расчётов зависит от полноты и достоверности загруженных данных
- Требуется подключение к интернету для загрузки данных через AlphaVantage
- Поддерживаются только компании, чья отчётность соответствует форматам баланса, отчёта о прибылях/убытках и отчёта о движении денежных средств

## 3. Описание логической структуры

### 3.1. Алгоритм работы программы
```
Начало
├── Аутентификация пользователя
├── Выбор компании:
│   └── Загрузка через AlphaVantage API (по тикеру)
├── Система проверяет полноту и валидность данных
├── Расчёт финансовых коэффициентов:
│   ├── Ликвидность (текущая, быстрая, абсолютная)
│   ├── Долговая нагрузка (D/E, IC Coverage)
│   ├── Рентабельность (ROA, ROE, ROS)
│   └── Динамика показателей (темпы роста, тренды)
├── Формирование рейтинга надёжности и индекса рисков
├── Визуализация аналитики:
│   ├── Графики динамики
│   ├── Межфирменное и отраслевое сравнение
│   └── Детализированные таблицы коэффициентов
├── Генерация отчётных документов (PDF/Excel)
├── Сохранение результатов в базу данных
└── Конец (вывод дашборда с оценкой)
```

### 3.2. Используемые методы
- **Архитектурные:** клиент-серверная модель, MVC, микросервисная организация (Go-сервер + Vue-клиент)
- **Объектно-ориентированное проектирование** (сущности: Компания, Отчётность, Коэффициент, Рейтинг)
- **gRPC + HTTP/JSON** для взаимодействия между сервером и клиентом
- **Асинхронная загрузка данных** через REST API (AlphaVantage)
- **Адаптивная вёрстка** с использованием CSS Grid/Flexbox
- **Контейнеризация** (Docker, Docker Compose)

### 3.3. Структура программы

#### 3.3.1. Основные модули:

1. **Модуль загрузки и валидации данных (Go)**
   - Интеграция с AlphaVantage API
   - Сохранение сырых отчётов в БД

2. **Модуль финансовых расчётов (Go)**
   - Вычисление коэффициентов ликвидности, долговой нагрузки, рентабельности
   - Анализ динамики (цепные/базисные темпы роста)
   - Расчёт интегрального индекса рисков
   - Построение рейтингов (на основе бенчмарков)

3. **Модуль аналитики и визуализации (Vue + TypeScript)**
   - Компоненты графиков (динамика показателей)
   - Таблицы сравнения компаний/отраслей
   - Интерактивные дашборды с фильтрацией

4. **Модуль отчётности (Go + шаблоны)**
   - Генерация документов для инвестиционного, кредитного и внутреннего использования
   - Экспорт в PDF, Excel, CSV
   - Кэширование готовых отчётов

5. **Модуль управления данными (PostgreSQL + Go)**
   - Репозитории для работы с компаниями, отчётами, коэффициентами
   - Миграции схемы БД
   - Резервное копирование и восстановление

6. **Модуль авторизации и разграничения доступа (Go)**
   - JWT-аутентификация
   - Роли: аналитик, кредитный специалист, инвестор, администратор

#### 3.3.2. База данных:

```
fin_assessment/
├── companies (компании: id, название, отрасль, ИНН)
├── financial_reports (отчёты: id_компании, период, тип_отчёта, данные_JSON)
├── coefficients (коэффициенты: id_отчёта, название_коэффициента, значение)
├── ratings (рейтинги: id_компании, дата, рейтинг, индекс_риска)
├── benchmarks (отраслевые бенчмарки: отрасль, коэффициент, эталонное_значение)
└── users (пользователи: логин, хеш пароля, роль)
```

### 3.4. Связи с другими программами
- Интеграция с внешним API AlphaVantage для автоматической загрузки отчётности по тикеру
- Взаимодействие с СУБД PostgreSQL через драйвер `pgx` (Go)
- Клиентская часть работает через HTTP/2 с сервером (REST + gRPC-web)
- Совместимость с системами CI/CD (GitHub Actions) для автоматической сборки и развёртывания

## 4. Используемые технические средства

- **Рекомендуемые:**

  - ОЗУ: 4 ГБ (сервер), 2 ГБ (клиент)

  - Сетевое подключение: 1 Гбит/с

### 4.2. Программные платформы
- **Операционные системы:**
  - Linux (Ubuntu 22.04+, Debian 12+, CentOS 9+) – основная среда

- **Контейнеризация и оркестрация:**
  - Docker Engine 20.10+
  - Docker Compose 2.0+

- **Веб-серверы:**
  - Nginx 1.20+ (в контейнере, статика + reverse proxy)

## 5. Вызов и загрузка

### 5.1. Способ вызова программы
Программа вызывается через веб-браузер по URL-адресу:

**http://[адрес_сервера]:[порт]/**

При использовании Docker Compose по умолчанию порт 80 (или 8080) пробрасывается на сервер.

### 5.2. Входные точки
- `/` – главная страница (авторизация или дашборд)
- `/dashboard` – аналитическая панель с рейтингами и графиками
- `/reports/upload` – загрузка финансовой отчётности
- `/reports/company/:id` – детальная оценка конкретной компании
- `/compare` – межфирменное/отраслевое сравнение
- `/api/v1/...` – REST-эндпоинты для клиентского приложения

### 5.3. Требования к памяти
- **ОЗУ на Go-сервер:** от 256 МБ (в покое) до 1 ГБ (при интенсивных расчётах)
- **ОЗУ на PostgreSQL:** от 512 МБ (для небольших баз) до 2 ГБ
- **Дисковое пространство для БД:** ≈ 10 МБ на 1000 отчётов
- **Кэш графиков и отчётов:** до 500 МБ (настраивается)

## 6. Входные данные

### 6.1. Характер и организация входных данных
- **Финансовая отчётность компании:** баланс (активы, пассивы, капитал), отчёт о прибылях/убытках (выручка, себестоимость, прибыль), отчёт о движении денежных средств (операционный, инвестиционный, финансовый потоки)
- **Режимы ввода:**
  - Автоматический запрос к AlphaVantage по тикеру (например, `AAPL`)
- **Параметры сравнения:** отраслевые индексы, бенчмарки (задаются администратором)
- **Авторизационные данные:** логин, пароль (передаются по HTTPS)

### 6.2. Формат и способ кодирования
- **Данные форм:** UTF-8, CSRF-защита, валидация на сервере и клиенте
- **Передача данных между клиентом и сервером:** JSON (REST API) и Protocol Buffers (gRPC)
- **Хранение в БД:** 
  - Отчёты – JSONB (PostgreSQL) для гибкой схемы
  - Коэффициенты – числовые типы (DECIMAL, FLOAT)
  - Даты – тип DATE
- **Обмен с AlphaVantage:** HTTPS GET-запросы, ответ в JSON/CSV

## 7. Выходные данные

### 7.1. Характер и организация выходных данных
- **Аналитические дашборды (на экране)**:
  - Интерактивные графики динамики коэффициентов за несколько периодов
  - Таблицы сравнения нескольких компаний или с отраслевыми бенчмарками
  - Рейтинговые шкалы и индикаторы рисков (цветовая маркировка)
- **Печатные/экспортируемые документы**:
  - Инвестиционное заключение (рейтинг, прогноз, риски)
  - Кредитное заключение (долговая нагрузка, покрытие процентов)
  - Внутренний отчёт финансового мониторинга (все коэффициенты, динамика)
- **Технические данные**:
  - Журналы событий (логи расчётов, ошибок)
  - Дампы БД для резервного копирования (формат SQL или архив)

### 7.2. Формат и способ представления
- **Веб-интерфейс:** HTML5 с адаптивным CSS (поддержка экранов от 360px до 4K)
- **Графики:** интерактивные SVG/Canvas (библиотека Chart.js или D3)
- **Экспорт отчётов:** PDF (с хедером, таблицами, графиками), Excel (XLSX), CSV
- **API ответы:** JSON (REST) или Protobuf (gRPC)
- **Резервные копии:** сжатые SQL-дампы, поддерживается автоматическое копирование на внешнее хранилище (S3, NFS)
